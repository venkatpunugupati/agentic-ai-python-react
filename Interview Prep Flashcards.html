Reading summary

What you learned, week by week

The progression matters: deterministic structure first, then autonomy, then the controls that keep autonomy useful.

Week 01

LLM foundations

You moved from calling a model to making its output dependable enough for code.

DAY 1

DAY 2

Prompt control

Week 02

Agentic systems from scratch

You built the moving parts frameworks usually hide—and learned where each part can fail.

DAY 1

Raw ReAct loop

Implemented Thought → Action → Observation with calculator, word_count, and get_current_time. A live time query proved the tool really executed.

DAY 2

Memory across processes

Persisted the full message list to memory.json, loaded it on startup, added --fresh, and tracked prompt-token growth between runs.

DAY 3

Compaction + grounding

Added rolling-summary compaction and a temporal grounding check. A stale saved time exposed the need to exclude volatile facts from summaries.

DAY 4

Plan, execute, replan

Generated tool-tagged plans, dropped unknown tools deterministically, chained prior results, and bounded CONTINUE / REVISE / DONE decisions.

DAY 5

Full composition

Integrated validate → plan → execute → verify → persist → compact. Debugging revealed evidence-chain, history-threading, and retry-scope failures.

Interview stories

The failures are the strongest material

Answer with the failure, the mechanism, the fix, and the engineering principle—not just the final code.

Stale time survived compaction

Symptom
A prior clock reading was summarized as a durable fact and reused the next day.
Fix
Add a volatile-fact drop-list; require current temporal queries to call get_current_time.
Principle
Memory needs retention policy, not just storage.

The planner invented [search]

Symptom
The plan referenced a tool that did not exist.
Fix
Parse each bracketed tool name and drop unknown steps before execution.
Principle
Prompts suggest behavior; deterministic code enforces contracts.

An indent doubled every step

Symptom
The grounding retry ran unconditionally, overwriting good results with second-pass deflections.
Fix
Move retry, recheck, and warning under if not grounded; verify single traces.
Principle
A correct final answer can hide a corrupted evidence chain.

Memory became write-only

Symptom
memory.json was loaded and saved, but new plan/execution prompts started from fresh history.
Fix
Thread bounded history through execute_plan and synthesis.
Principle
Persistence is not memory until the read path reaches inference.

Tool-called ≠ answer-grounded

Symptom
A current-leader question called the time tool, then answered from stale model knowledge.
Fix
Future verifier must check derivation and source support, not mere tool invocation.
Principle
A trace can prove an action happened without proving the claim used its result.

Full history contaminated style

Symptom
Synthesis copied plain assistant prose, omitted the required markers, and hit max steps.
Fix
Restate the exact response contract at the end of the synthesis prompt; do not persist stopped runs.
Principle
Recent examples can overpower distant instructions.
